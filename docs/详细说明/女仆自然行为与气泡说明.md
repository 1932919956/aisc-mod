# Agnes 女仆伙伴：自己玩生存、气泡对话、视觉闭环、地标记忆、猎杀与下矿

2026-09-21，适用于 Minecraft 1.20.1 / Forge 47.4.18 / 车万女仆 1.5.3。

一～八章（1.0.4）：自然行为与气泡。**第九章（1.0.5）**：视觉闭环。**第十章（1.0.6）**：记忆化地标。**第十一章（1.0.7）**：主动猎杀与安全阶梯下矿。

1.0.4 解决的是两个问题：**她看起来不像活人**，以及**她从不主动开口**。办法不是给模型加更多话，而是把「什么时候说话、说什么」改成由本地判断，并且都走车万女仆原生气泡；同时让她在两分钟规划间隔里也一直有事情做，而不是站着等下一条指令。

## 一、她说话改用原生气泡

以前她的回复只出现在聊天框里，而且只有模型返回 `say` 时才有内容。现在：

- **说出的话**：用女仆自己的对话气泡（车万女仆原生的文字气泡）。
- **心里的想法**：用女仆原生的「思考气泡」（灰色斜体文字，带阴阳球图标）。

分工是固定的：气泡里是她说的话和她在想的事；**执行的行动结果仍然只走物品栏上方的提示**，因为那是程序验证过的数据，不能和她的话混在一起。这样「她要去做」和「她已经做完」不会互相冒充。

## 二、主动开口不再只靠模型

模型返回的 `proactive_chat` 是可选字段，实际上很少填写，所以以前她几乎不会先开口。现在改成本地驱动，**不需要联网、不需要密钥**：

| 她会主动说话的场景 | 说明 |
| --- | --- |
| 你重新进入存档 | 认识你之后会用约定的称呼，并说出她当时在做的事 |
| 天亮 / 入夜 | 一天各一次，说出今天的打算或提醒准备火把和住处 |
| 低血量、附近有敌对生物 | 紧急情况，不受普通冷却限制 |
| 受伤到七成血以下 | 说明先修整 |
| 你血量偏低 | 提醒你先吃东西或退开 |
| 背包没有食物 | 说明要去找吃的 |
| 下雨、雷雨 | 各有一句 |
| 熟睡度上来、亲密度跨档 | 说自己的偏好和关系变化 |
| 长时间没有新安排 | 说出她正在做或想做的事 |

其他规则：

- 你刚说过话后约 45 秒内她不会插嘴。
- 普通主动说话的间隔约 75 秒；紧急情况立刻说。
- 同一句不会连续说两次；一句话像「我已经采集完了」这种冒充行动汇报的内容会被拒绝。
- 想让她安静：说「先别主动说话」「安静一点」「别说话」。想恢复：说「可以主动聊天了」「多陪我聊聊」「多说点话」。
- 规划过程也会显示在思考气泡里：准备规划时显示「看看周围，想一件现在能做的事……」，拿到计划后显示她这一轮的目标。

## 三、她开始有自己的生活节奏

**空闲就自己找活干。** 两分钟规划之间的空档，她不再原地站着，而是自己接手能在当前条件启动的原生工作，并用气泡说一句：

- 食物少于 6 份：先摘附近成熟的甜浆果；没有浆果就先照看农田，再不行就去水边钓鱼。
- 食物够：去田里或水边忙一会儿。
- 这些都做不了：回到空闲并如实说明「这里的活干完了」，把情况交给下一轮规划。
- 一份工作她至少会做约五分钟才会换，不会来回换任务显得很慌。
- 只在**自主活动开启**、她确实空闲、没有战斗、没有受伤、你也没有给她安排事情时才会接管。你手动改任务、坐下、战斗、睡觉、修整、或你发指令时都会立刻让位。

**条件齐了会自己出远门。** 当食物、木头、石头都够，血量和时间也合适，而她两游戏日没出过门时，她会挑一个已扫描到的落脚点自己走过去。走到之后，她的自由活动点会跟着前移——也就是**她在那边安顿下来继续生活**：在附近采集、种田、钓鱼，而不是走一圈又绕回老地方。夜里和血少时不会出门。

**到达地点会说一句。** 走到落脚点会说「到这里了，先看看周围有什么。」，不再只是默默刷一条状态。

## 四、给她更像玩家的行动方针

交给 Agnes 的自主指令改成「继续按你自己的生存节奏玩下去」，并在系统提示里明确要求：

- 保持一两个进行中的打算（例如「把屋子盖完」「换铁工具」），推进下一步，而不是每轮从头开始或重复已经受阻的动作。
- 条件不足时一次安排多步采集和制作，而不是一步一停。
- 一次游戏时间里要有变化：有时在基地附近干活，有时走到新的落脚点；原生任务（种田、钓鱼、剪羊毛、喂动物、除草）在工具和场地允许时都可以用。
- 不要囤积：大约 16 份食物、8 个原木、24 个石头就够，其余精力放在工具、住处和探索上。
- 跟作息走：白天干活、入夜前准备光源和安全住处，尊重自己的睡眠时间。
- 真的什么都做不了时，说出具体缺什么，并考虑换个地方，而不是假装在忙。

## 五、可验证性和边界

- 她仍然只调用已经接入的动作和女仆原生任务，**不会**自由建造任意建筑、开机器、下矿道或自主通关。
- 「像真人」指的是行动节奏和说话方式，不是能力上限。她依然可能选错、走不到、被地形挡住。
- 本地说话和空闲找活都不调用付费接口，断网时她照样会说话和有反应；只有需要决策时才会请求 Agnes。
- 所有世界改动仍然检查 `mobGriefing` 和 Forge 保护事件。想完全停下来用 `/aipartner autonomy off`，她仍会跟着你并可以聊天。

## 六、本次新增/变更的命令

| 命令 | 用途 |
| --- | --- |
| `/aipartner maid speak` | 立刻用气泡说一句她当前的心情和目标，用来确认气泡是否正常显示；不调用接口 |
| `/aipartner maid personality` | 现在会显示亲密度、一起度过的天数、她对你的称呼 |
| `/aipartner maid bind` | 绑定后默认开启自主活动，同时默认开启主动说话 |

## 七、安装

把 `安装用-mods\agnespartner-1.0.5-portable.jar` 放进游戏 `mods` 目录（替换旧的 agnespartner JAR），车万女仆保持本包提供的 1.5.3。已有存档的绑定、密钥、记忆都会继续使用，不需要重新绑定。

测试提示：绑定后等十来秒，输入 `/aipartner maid speak`，如果她头顶出现气泡就说明这条链路正常。之后她会在合适的时机自己开口。再输入 `/aipartner maid sight` 可以看清她此刻"看到"了什么。

## 八、验证到什么程度

本次改动的验证方式和边界如下，请按这个预期使用：

- **已确认**：全部代码在 Forge 47.4.18 + 车万女仆 1.5.3 的真实接口下编译通过（用的是本包附带的那个 1.5.3 JAR 作为编译依赖）。
- **已确认**：两个正式 JAR 都检查过内容，包含新的气泡桥接、本地说话和人格类，没有混入测试类；portable 版带 portable 标记，普通版不带。
- **已确认**：气泡调用本身是照着车万女仆 1.5.3 的实际字节码写的，用的是它自己的 `getChatBubbleManager()`、`addTextChatBubble()`、`addThinkingText()`、`addTextChatBubbleIfTimeout()` 和 `removeChatBubble()`，不是自建渲染。
- **未完成**：没能在这台机器上跑通「带车万女仆的 Forge 游戏测试」。原因是车万女仆 1.5.3 的开发环境映射参考表里缺一条字段映射（`MobInteractMixin` 的 `f_21350_`），Forge 开发服务端在加载它自己的 mixin 时就失败了，和本次改动无关，也不影响正式游戏（正式游戏用 SRG 名称，和它发布时一致）。所以**气泡和自主行为的实际画面效果需要你进游戏确认一次**，用 `/aipartner maid speak` 最快。
- **未实测**：本次没有对整合包内的帧率、游戏刻耗时做前后对比；新增的本地判断都是每秒一次的轻量检查（读几个 NBT 字段和方块状态），扫描和小屋逻辑未改动。

需要重新构建时：源码在 `work/agnespartner-build`，本机已缓存 Forge/Minecraft 依赖，可以离线执行 `build-agnes-release.ps1`（该脚本用 `-Pportable` 与 `-Pmod_version=...` 分别产出 portable 版和普通版）。

## 九、视觉闭环（1.0.5）

你要的是：**她的视觉反馈给 Agnes，Agnes 判断她在玩生存、下一步该做什么，她去执行**。这条链路本来就在跑，1.0.5 做的是把它补实，因为原来有三个地方让它不够可靠。

### 原本的循环

每两分钟一次：

1. 让女仆自己的第一人称摄像头在客户端补拍一张 640 像素画面；
2. 画面连同「眼睛位置、朝向、拍摄时间、FOV」一起交给 Agnes；
3. 同时带上结构化状态：背包、装备、血量、100 格扫描到的可操作目标 ID、附近生物、仓库、合成选项、上一步的真实结果；
4. Agnes 返回 JSON 行动计划，本地执行器逐条真实执行；
5. 执行结果再喂给下一轮。

### 原来不可靠的三个地方

- **画面可能过期**：拍摄在请求前 1.5 秒才发起，之后还要花时间构建很长的提示词，所以送出去的图可能是十几秒前的，甚至被接口拒图后退化成纯文字。
- **平面截图说不清距离和名字**：模型没法从像素判断"那棵树有 8 格远""那个方块能不能走过去"，所以只能靠文字描述猜，容易选到不存在的目标。
- **计划之间她是盲的**：中间遇到挡路、目标消失、工具损坏，只能干等两分钟的下一轮，而真人会当场换条路。

### 1.0.5 的三项改动

**一、决策前尽量给一张新画面。** 规划发起时先主动补拍一次；如果拿到手的画面超过 5 秒，她会先在心里说一句「先把眼前的画面看清楚……」，再补拍一张后才决策。补拍失败不会卡住她——直接用游戏状态和视角清单继续，并在状态里写明"本轮没有有效画面"。

**二、新增「她眼前看到什么」的机器可读清单。** 这一项和画面一起发给 Agnes，名字叫 `sight`：

- `forward_ray`：她视线正前方第一个实体方块是什么、多远、朝哪一面、能不能走过去、能采集为什么；
- `visible_columns`：视野锥内最近的一圈方块，每条的方块 ID、距离、方向（正前/左侧/右侧/身后）、是否可达，可采集的还会直接给**和动作系统一致的目标 ID**；
- `walkable_ground_ahead`：正前方是不是空地；
- `nearby_notable_blocks`：身边 4 格内值得注意的东西（工作台、熔炉、箱子、水、岩浆、床、农田、矿石等）。

图和清单是互相印证的关系：**图负责"情况是什么样"，清单负责"确切是什么、有多远、能不能碰"**。清单里没有的东西，她不允许说看见了。

**三、她能自己转头观察，并新增受阻快速重看。**

- `look`：转头看向某个位置（给 `target_id`）或指定角度（`yaw`/`pitch`），保持约 4 秒。因为第一人称摄像头跟着头部朝向，所以她**可以为了看清某样东西而主动转过去**，下一轮观察就会带上这个方向。这不算世界改动，休息时也允许。
- `scan_area`：原地环视一圈（8 个方向），结束时补拍一张画面，让她对四周有一次完整观察。
- **受阻即时重看**：当执行器明确"走不到、被地形挡住、目标消失、超时、任务不可用"这类**世界拒绝了她**的情况时，她会在约 **45 秒**后就重新看一眼再决定，而不是干等两分钟。注意这不包括网络或接口失败——那不是换个角度看世界能解决的。她也可以选择"再观察一下，先别动"来主动请求更快的下一轮。
- `/aipartner status` 现在会显示"最近受阻"原因和快照间隔；`/aipartner maid sight` 可以本地打印她此刻的视觉状态，不花接口费用。

### 如何确认它在工作

1. 绑定并开启自主活动，等两分钟左右；
2. 输入 `/aipartner maid sight`，应该看到：镜头状态（是否就绪/几秒前拍的）、正前方是什么、视野内可见列数、可达目标的 ID 列表。如果这里能看到方块和目标 ID，就说明感知链路正常；
3. 输入 `/aipartner status`，看"上次视觉请求"是"已发送女仆第一人称画面"还是"改用游戏状态"。如果是后者，通常是开了光影/极佳画质（会在状态里写明），关闭光影并选流畅或高品质即可恢复；
4. 想看她是否在主动观察，注意她的头会转，并且气泡里会出现"先把眼前的画面看清楚……"。

### 视觉部分的边界（不要期待超过这些）

- 画面只包含**客户端已加载**的地形；未加载的远处不在图里，清单也只读已加载区块。
- 单张平面图**没有深度**。"清单"能给出距离和可达性，但"图里那棵树后面有什么"仍然要靠走过去再看一次。
- 开光影或"极佳"画质时独立摄像头会暂停，只剩游戏数据；这是原有限制，1.0.5 没有改。
- 专用服务器上仍然拿不到本机女仆摄像头画面，只能靠游戏数据。
- `look` / `scan_area` 会改变她的头部朝向和移动方向，这在**你正手动操作她**或者她正在战斗时可能显得突兀；目前它们只在 Agnes 自主决策里被调用，你发的指令不会触发。

### 这些改动的验证程度

- 已确认：全部代码在 Forge 47.4.18 + 车万女仆 1.5.3 的真实接口下编译通过；两个正式 JAR 内容已逐项检查（含 `MaidSight`、`MaidBubble`、`MaidVoice`，无测试类，portable 标记正确）。
- 已确认：视野清单读取的全部是服务端已加载区块的方块状态和碰撞形状，和采集动作使用同一套分类（`MaidFieldwork.kind`），所以清单里的 `target_id` 就是执行器接受的格式。
- 未完成：仍未能跑通带车万女仆的 Forge 游戏测试（原因见第八章：车万女仆开发环境的 mixin 映射缺项），所以**画面、清单、转头观察的实际效果需要你进游戏看一眼**，`/aipartner maid sight` 是最快的确认方式。
- 未实测：没有做帧率与游戏刻耗时的前后对比。`sight` 只读她周围 24 格内的方块（每轮一次），`look`/`scan_area` 只是设置头部旋转，理论上开销很小，但没有实测数据。

## 十、记忆化的地标（1.0.6）

这是让"自己玩"有连续性的那一环。没有它，她每次路过同一片水、同一处矿、自己的营地都要重新观察一遍——这正是"看起来像个没有生活的机器人"的来源。

### 她会记住什么

地标写在她自己的存档数据里（随女仆实体保存），最多 **24 处**，每处记录：类型、名字、坐标、维度、去过几次、失败几次。

| 类型 | 什么时候写下来 |
| --- | --- |
| 水源 | 100 格扫描时**真正看到**水，并且她确实走到过附近 |
| 矿点 | 她**实际采集**过石头／深板岩／煤矿／铁矿的位置 |
| 浆果丛／农田 | 她**实际采摘**过成熟甜浆果的位置 |
| 小屋 | 她自己**实际建成** 5×5 小屋的位置 |
| 工作台 / 熔炉 | 她**自己放置**的这些方块 |
| 营地 | 她实际采集过原木的位置 |

**关键约束：地标只由她真正做过的事产生，模型不能凭空写入。** 这是这套记忆可信的原因。

### 记忆怎么用

- 每次交给 Agnes 的状态里多了一段 `memory.remembered_places`：`target_id`（形如 `landmark:3`）、名字、类型、距离、去过几次；上次去没找到的还会标注"可能已经没了"。
- 新增动作 `visit_landmark`（用 `target_id`）。**走记忆里的地点不需要重新观察**——这正是它的意义。她按记忆分段寻路过去，路上有 5 分钟总时限和 15 秒无进展判定。
- **到达后核对**：按类型检查那里是否还是原来的样子（水还在不在、石头／矿还在不在、工作台／熔炉／箱子／农田还在不在、小屋附近是否还有建筑）。对得上就记一次"去过"，记不住就对不上。
- **对不上会告诉她，也会让她说话**：气泡里会出现"这里和我记得的不一样了……"，并把这次记成一次失败。**连续两次对不上就自动忘掉这个地方**，不会让她一次又一次跑去同一个空地方。
- 忘了什么也会记进她的"行动记录"，下一轮 Agnes 能看到。

### 怎么确认它在工作

1. 先让她在自主模式下干点活：采一次石头或木材、盖一次小屋、放一次工作台。最有把握的是**采一次石头**（矿点）或**让她盖小屋**；
2. 输入 `/aipartner maid landmarks`，应该看到类似 `landmark:0 我挖过的矿点（mine）距离 12 格，去过 1 次`；
3. 带她走远一些，或在状态里看到她把 `visit_landmark` 当作下一步，观察她是否会自己走回去；
4. 想验证"核对"逻辑：把那个位置的方块挖掉／水填掉，再让她去一次。她到达后应该说"和记得的不一样"，第二次之后该地标从列表消失。

### 边界

- 记忆**按维度分开**记录。她不会尝试跨维度走回主世界的地标（列表里只会出现在当前维度的）。
- 24 处是上限，满了会优先忘记"去过次数最少、最久没去"的那条。
- 地标记的是**坐标假设**，不是永远正确的事实。她会核对，但核对是粗粒度的（比如"附近还有没有石头"），玩家把一整片区域改造成别的东西时，她可能仍认为那里是矿点。
- 她不会因为记得某个地方就**主动传送**过去，仍然是真实寻路；隔山隔海走不到就会放弃这次。
- 与 1.0.5 一样的限制：这些行为只在自主活动开启、她空闲且没有战斗时生效。

### 这些改动的验证程度

- 已确认：全部代码在 Forge 47.4.18 + 车万女仆 1.5.3 的真实接口下编译通过；1.0.6 两个 JAR 内容已逐项检查（含 `MaidLandmarks`、`MaidSight`、`MaidBubble`、`MaidVoice`，无测试类，portable 标记正确）。
- 已确认：写入地标的四个来源（采集、采摘、建成小屋、放置工作台／熔炉）都是既有代码里"已经真实发生"的分支，不在失败或模拟路径上。
- 未完成：仍未能跑通带车万女仆的 Forge 游戏测试（原因见第八章），所以**地标的写入、走回去、到达核对的实际表现需要你进游戏验证一次**，用 `/aipartner maid landmarks` 最快。
- 未实测：长期存档里 24 处记忆的读写开销没有实测；每轮只是读取一个 NBT 列表并算距离，理论上可以忽略。

## 十一、猎杀与下矿（1.0.7）

这一版补的是最大的能力缺口：**吃肉和拿铁**。原则是"只做最安全的那一档"，宁可慢、宁可停，也不赌。

### 主动猎杀（`hunt`）

之前她只有在被攻击时用女仆原生战斗还手，不会主动去打猎。现在她会**主动出门打一只动物换肉**。

- **只猎取野生的、没有名字的、没被驯服的动物**。玩家自己的宠物、命名过的动物、其他女仆、玩家本人一律不碰。
- 她走到目标身边挥击，按**真实攻击力**扣血（手里的剑比木棍强），怪物会正常反击她；动物死了才走**原版掉落表**，掉什么算什么，能放进背包的进背包，放不下的留在原地交给她的拾取机制。
- 追不上的情况：两分钟没靠近，或者连续 15 秒没有拉近距离就放弃这只，并进约 30 秒冷却，不会死追一只跑得快的牛。
- **食物少于 6 份时，打猎优先于摘浆果和钓鱼**——这是本地判断，不花接口费用。
- 模型也能用 `hunt` 动作指定目标（`huntable_animals` 列表里带 `target_id`、类型、距离、血量、食物价值），或只给 `target_kind=animal` 让执行器自己挑最近的。
- 打完会说一句（"打到一只牛，今晚有吃的了"）并记一个"营地"地标。

**边界**：这不是一套战斗系统。她不会主动去清怪、不会用弓箭、不会走位风筝；面对铁傀儡或远程怪基本是硬碰硬，血量掉到一半就放弃回家。`mobGriefing` 关闭时整个猎杀功能直接拒绝启动。

### 安全阶梯下矿（`dig_shaft`）

按你选的方案：**只挖阶梯竖井，遇水或岩浆立即停。**

- 她朝自己面向的方向，**一次挖一格台阶往下**：挖开前方的落脚块和它下方、头顶、更上方，然后走进新台阶。挖过的台阶**就是回程的路**，所以不存在把自己困死的情况。
- **永远不会挖穿到水或岩浆**：每一步开挖前先把四个待挖方块检查一遍，只要其中任何一个是液体，她立刻停止并向你报告，然后走回地面。沙子、沙砾、可疑沙这类会塌下来埋住台阶的方块同样会让她停下。
- 另外会停下来的情况：血量掉到一半、被战斗打断、坐下或睡觉、找不到能挖石头的镐、方块被领地保护拒绝、走了十分钟还没到目标深度。
- 深度由 `count` 指定（4～24 格，默认 12），她只会挖到"地下 N 格"，不会无限往下。
- **每 6 格放一支火把**（她自己背包里的火把），所以井里是亮的，不会漆黑一片。
- 挖完在**井口记一个"矿点"地标**，以后可以 `visit_landmark` 直接走回来。
- 挖到的圆石、煤、粗铁等按原版掉落**真实进包**；途中看到铁矿或煤矿会说出来并继续往下。

**边界（说清楚，别期待超过这些）**：她**不会**顺着矿脉横向挖、**不会**挖到基岩、**不会**清理会让台阶塌掉的流沙，也**不会**自己去洞穴里探索。它是一条通向石层和浅层铁的楼梯，不是矿井。

### 怎么试

1. 找一片有牛的草地，开自主活动，把她背包里的食物清空或吃到 6 份以下，等一会儿——她应该会自己去追牛，气泡里说"去打一只牛弄点吃的"；
2. 输入 `/aipartner maid landmarks`，猎杀成功后应该多出一个"我的落脚点／营地"；
3. 在安全的地方（**别站在水边或岩浆边上**）看她说要下矿，或者直接问她"你挖一条竖井下去看看有没有铁"；观察她是不是一格一格往下、并且记得放火把；
4. `status` 里能看到 `dig_result`：当前深度、是否看到矿、以及停止原因。

### 这些改动的验证程度

- 已确认：两个正式 JAR 内容已逐项检查，包含 `MaidHunt` 与 `MaidDig`，没有混入测试类，portable 标记正确；全部代码在 Forge 47.4.18 + 车万女仆 1.5.3 真实接口下编译通过。
- 已确认：破坏方块走的是和采集完全相同的安全通道（`BlockEvent.BreakEvent` + `mayInteract` + 原版掉落表 + 工具耐久真实消耗），放置火把复用了已验证过的放置逻辑。
- **未实测（这次尤其重要）**：带车万女仆的 Forge 游戏测试仍然跑不起来（第八章的原因），所以**猎杀的伤害与掉落、阶梯下矿的走位与停止判定都还没有在真实世界里跑过**。下矿是会真实改变地形的功能，建议你**先在创造或备份过的存档里试一次**，确认台阶走得通、停止逻辑正常，再放进主存档。
- 已知设计取舍：竖井是"一条楼梯"，所以效率低于真人挖的阶梯加横巷；如果实测发现她经常在第一格就找不到可行的落脚点，需要再放宽一步的挖掘范围。

## 十二、三种定型蓝图（1.0.8）

原来只有一种 5×5 小屋。现在有三种**固定蓝图**，都走同一套已验证的机制：真实走近、逐块放置、中断可续建、材料先核算。

| 蓝图 | 尺寸 | 材料 | 特点 |
| --- | --- | --- | --- |
| `hut` 小屋 | 5×5 | 约 78 块同种木板/石材、1 扇橡木门、1 支火把 | 最便宜最快，一间房，第一次过夜用 |
| `cottage` 带储物间的石屋 | 7×7 | 约 175 块同种木板/石材、1 扇橡木门、2 支火把 | 中间有一道隔墙和一格门洞，**里间可以放箱子和熔炉**，两支火把照亮两间 |
| `farm` 围栏菜园 | 6×6 | 约 20 个栅栏、16 块耕地（farmer's land 方块，需她自己携带） | 一圈栅栏围住 4×4 菜地，南侧留一格出入口；**只有背包装着耕地时才会建**，不会围一块没法种的地 |

三种的规则：

- **是用场地 ID 前缀选蓝图的**：`hut:…` / `cottage:…` / `farm:…`。每种场地在 `building.clear_site_ids_by_kind` 里分别列出，模型必须用同一种的场地和蓝图，混用会被拒绝。
- **材料先核算**：开工前检查背包是否够全部材料，不够会明确说"还需要 X ×N，当前 M"，不会盖到一半才发现缺。
- **中断可续建**：工地、蓝图种类和材料都记录在女仆身上，重进存档后能接着盖；`saved_site_id` / `remaining_materials` 会告诉她还差什么。
- **完成会记账**：三种都会记成地标（小屋和石屋记 `house`，菜园记 `farm`），以后能按记忆走回来。
- 一次只允许有一个未完成工程；换了蓝图种类要先完成或放弃旧的。

**边界**：仍然是三种固定图纸，**不能自由设计**。7×7 石屋占地和材料都明显更多，所以模型被要求在食物和工具稳定、石头够用之后再考虑；菜园会真实消耗她的耕地方块，没有耕地就会拒绝。

### 怎么试

在平坦空地上说"你盖一间带储物间的石屋"或"围一个菜园"，或者直接看 `building.clear_site_ids_by_kind` 里的场地。`/aipartner status` 里能看到 `BuildResult` 的逐块进度（例如 `实际建造进度 137/196（带储物间的 7×7 石屋）`）。

### 验证程度

- 已确认：两个正式 JAR 内容逐项检查（含三种蓝图数据、`MaidHunt`、`MaidDig`、`MaidLandmarks`、`MaidSight`、`MaidBubble`，**没有**混入验证脚手架），portable 标记正确；全部代码在 Forge 47.4.18 + 车万女仆 1.5.3 真实接口下编译通过。
- **未实测**：真实世界里逐块施工的走位与放置，以及三种蓝图的成品外观，都还没有跑过。我写了完整的运行时断言（逐项检查蓝图无重复格子、无越界格子、材料都是真实方块、石屋恰好 1 门 2 火把、小屋 1 门 1 火把、耕地只在地面层、场地 ID 前缀正确，以及气泡、人格、地标、视野、猎杀规则），但**这些断言一次都没有真正运行成功**：带车万女仆的 Forge 游戏测试需要**服务端 jar**，而 PCL 只装了客户端；我用 `client-extra` 顶替服务端、以及直接启动客户端两种方式都卡在 Forge 自己的 JPMS 模块导出冲突上（`minecraft` 与 `client` 模块同时导出同一批包），与 mod 代码无关。所以这一节的结论只有前三项（契约、编译、包内容）成立。

## 十三、围棋卡死与"光说不做"的修复（1.0.9）

这是你实测反馈的两个问题，根因查清了。

### 问题一：她总是去下围棋

**根因**：车万女仆的"下棋"任务（`touhou_little_maid:board_games`）会让女仆**坐在棋盘上**。在这种坐下状态里 `GoMaid.playing()` 恒为真，于是执行器的第一道检查 `if (GoMaid.playing(...)) return "正在下围棋，暂不执行世界行动";` 会**每次**拒绝执行。而同时，"下棋"这个任务出现在我交给模型的 `available_tasks` 候选列表里——模型偶尔选了它，就进入了一个死循环：坐下下棋 → 之后每一轮规划都被拒绝 → 只能回一句"我在下围棋"。

**修复**：
- 围棋任务**不再进入 Agnes 的生存候选任务**（本地过滤，模型看不到、选不了）。玩家想下棋仍然用 `/aipartner go`，刻意开始，不受影响。
- 如果她在棋盘上而新的行动安排到了，**她会放下棋局去做事**，并说一句"我先放下这局棋去做事；想继续下棋再说一声就行"，而不是把整轮安排丢掉。

### 问题二："基本上光说不做"

**修复**：
- **连续只说不做的升级处理**：前三次立刻重判（不再等两分钟）；连续到第 4 次时她会直接在聊天里说"我这两轮只在想事情，没有真的动手"，同时把受阻原因交给下一轮。这样你能立刻看出是模型在空转，而不是她"安静地没事干"。
- **交付给模型的指令里写明了不许只说不做**：返回 `keep` 而没有行动时，必须挑一个当下最小可执行的动作（砍一根木头、打一只动物、走去记住的水源、放一支火把），并且会被告知"你已经连续空转 N 轮"。
- **气泡里说的是她真正要做的事**：空闲找活时会先显示"先做：<具体那件事>"，而不是只显示"在想怎么推进"。
- 行动反馈也改成如实描述：连续空转时显示"已经连续 N 轮没有执行任何实际动作"，而不是含糊的"未选择动作"。

### 怎么确认修好了

1. 重启游戏，进存档；
2. 输入 `/aipartner autonomy on`；
3. 在**离棋盘远一点**的地方等两分钟。正常情况下你会看到她把某件具体的事说出来（气泡）并且**真的去做**：走过去、砍东西、打猎；
4. 如果她还是只说不做，聊天里会在第四轮出现"我这两轮只在想事情，没有真的动手"——把这句连同 `/aipartner status` 发我，那就是模型侧的问题，我会调整指令而不是机制。

### 验证程度

- 已确认：编译通过；两个 JAR 内容逐项检查（含 `survivalTask` 过滤、放下棋局的逻辑、空转升级提示），无测试残留，portable 标记正确。
- **未实测**：这次修改同样没有在真实世界里跑过（原因见第八章与第十二章末）。所以"她是否真的不再被围棋卡住"需要你这一轮进游戏确认——这是本次修复最关键的一条验证。
